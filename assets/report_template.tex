\pdfbookmark[1]{1. What this project is about}{1Whatthisprojectisabout}
\section*{\color{bambergnavy} 1. What this project is about}
Language models can write text that sounds very good. But sounding good is not the same as understanding what a sentence really means. In this project, I wanted to check a simple thing: when a model is given one sentence (the premise) and another sentence (the hypothesis), can it tell whether the second sentence must be true, or whether it only sounds likely?

This matters because many model mistakes come from guessing what is common in the real world instead of following what the words actually say. I built a small benchmark and a Python testing pipeline to check this in a clear and repeatable way.

\FloatBarrier
\pdfbookmark[1]{2. Research questions}{2Researchquestions}
\section*{\color{bambergnavy} 2. Research questions}
I worked with these main questions:
\begin{enumerate}[leftmargin=*]
    \item Can selected language models tell the difference between a real inference and a plausible but wrong one?
    \item Does the prompt style change the result? I tested zero-shot, few-shot, and chain-of-thought prompts.
    \item Do bigger or proprietary models do better than smaller open models?
    \item What kind of mistakes do models make? For example, do they over-accept likely statements, or do they miss presuppositions and negation?
\end{enumerate}

\FloatBarrier
\pdfbookmark[1]{3. The dataset used}{3Thedatasetused}
\section*{\color{bambergnavy} 3. The dataset used}
The main benchmark has 180 items. Each item has a premise, a hypothesis, and a gold label (Yes or No). The data is balanced:
\begin{itemize}[leftmargin=*]
    \item 60 lexical entailment items (30 Yes, 30 No)
    \item 60 presupposition items (30 Yes, 30 No)
    \item 60 plausible non-entailment items (30 Yes, 30 No)
\end{itemize}
I also made 30 perturbation items. These are small rewrites of original items. The meaning stays the same, so the gold label should stay the same. This helps check if a model is stable when wording changes.

\pdfbookmark[1]{4. How I built the evaluation}{4HowIbuilttheevaluation}
\section*{\color{bambergnavy} 4. How I built the evaluation}
\subsection*{\color{bambergnavy} Prompt styles}
I used the same task definition in all three prompt styles so the comparison is fair:
\begin{itemize}[leftmargin=*]
    \item \textbf{Zero-shot:} give the task rule and ask for Yes/No.
    \item \textbf{Few-shot:} give the same rule plus 4 example answers. These examples are not in the benchmark.
    \item \textbf{Chain-of-thought:} give the same rule, ask for short reasoning, and require the last line to be \texttt{Final Answer: Yes} or \texttt{Final Answer: No}.
\end{itemize}

\subsection*{\color{bambergnavy} Models and backends}
The code supports these backends:
\begin{itemize}[leftmargin=*]
    \item Ollama for local open-weight models like Llama 3 and Mistral.
    \item Hugging Face for local transformer models, with exact Yes/No token probability for direct prompts.
    \item OpenAI API for models like GPT-4o.
\end{itemize}
I ran real local tests through Ollama on four models: \texttt{llama3:latest}, \texttt{mistral:7b}, \texttt{mixtral:8x7b}, and \texttt{qwen2.5:7b} (qwen was an extra model, not in the original proposal). I also ran \texttt{openai/gpt-oss-20b} via Groq (OpenAI-compatible API) and \texttt{@cf/meta/llama-3.3-70b-instruct-fp8-fast} via Cloudflare Workers AI (a quantized fp8-fast variant of Llama 3.3 70B; close to the proposal model but not the same local/HF exact setup). I also attempted a free OpenRouter Nemotron run; the key was later fixed, but the run hit the OpenRouter free daily limit at 59/540 cached predictions and was not completed. I ran the full 180-item benchmark with all three prompt styles, plus the 30 perturbation items. I did not run all models named in the original proposal (still missing OpenAI GPT models due to API quota, and optional HF exact-logit check pending approval). The numbers below come from those saved result files.

\subsection*{\color{bambergnavy} How answers are scored}
\begin{itemize}[leftmargin=*]
    \item For normal prompts, the code reads the Yes/No answer.
    \item For chain-of-thought, only \texttt{Final Answer: Yes} or \texttt{Final Answer: No} is accepted. Anything else is marked \texttt{Invalid}.
    \item Invalid answers count as wrong, but they are also counted separately so we can see format problems.
\end{itemize}

\subsection*{\color{bambergnavy} Main metrics}
These are the main numbers I would use to compare models:
\begin{itemize}[leftmargin=*]
    \item Accuracy
    \item 95\% bootstrap confidence interval for accuracy
    \item Macro-F1
    \item Balanced accuracy
    \item Per-category accuracy and Macro-F1
    \item McNemar test for paired model/prompt comparisons
\end{itemize}

\subsection*{\color{bambergnavy} Extra diagnostic metrics}
These are useful, but they should be read with care:
\begin{itemize}[leftmargin=*]
    \item False positive rate (model says Yes too often)
    \item False negative rate (model says No too often)
    \item Invalid rate
    \item Accuracy without contested items
    \item Heuristic error type labels
    \item Perturbation consistency
\end{itemize}

\FloatBarrier
\pdfbookmark[1]{6. What I checked and fixed in the code}{6WhatIcheckedandfixedinthecode}
\section*{\color{bambergnavy} 6. What I checked and fixed in the code}
I ran the tests before and after my fixes. The final result was: \textbf{13 passed}.

The main bugs I found and fixed were:
\begin{enumerate}[leftmargin=*]
    \item \textbf{Cache type bug:} Old cache saving could turn some values into strings. I fixed it so booleans, numbers, and missing values stay correct.
    \item \textbf{Stale cache bug:} If a benchmark item changed but the ID stayed the same, old cache could be reused by mistake. I added a check for premise and hypothesis.
    \item \textbf{Hugging Face crash:} If a tokenizer had no single-token Yes/No option, the code crashed in a confusing way. I added a clear error message.
    \item \textbf{Ollama logprob bug:} Sometimes the chosen Yes/No token was not inside top logprobs. I fixed the parser to include it.
    \item \textbf{OpenAI logprob bug:} The first token can be a blank line or space. I changed the code to skip empty tokens.
    \item \textbf{Contested item bug:} ``False'' as a string can be read as true in Python. I fixed the contested check so it reads values safely.
    \item \textbf{Metrics and analysis cleanup:} I used nanmean where needed, removed an unused import, made analysis ignore duplicate rows, and made it safer when \texttt{error\_type} is missing.
\end{enumerate}
I also added regression tests for these cases so the same bugs are less likely to come back.

\subsection*{\color{bambergnavy} What I noticed}
Among the four local Ollama models, Qwen2.5:7b was strongest (about 87--91\%), followed by Mixtral:8x7b (about 77--86\%), Mistral:7b (about 69--76\%), and Llama3:latest (about 59--77\%). Across all tested backends, Cloudflare's Llama 3.3 70B variant achieved the highest accuracy (96.67\% in few-shot and CoT). Groq's gpt-oss-20b also reached 90.56\% in CoT.

Plausible non-entailment was the hardest category for most models, especially Llama3:latest (40--70\%) and Mistral:7b zero-shot (51.67\%). This suggests world-knowledge over-acceptance is a real problem.

Few-shot helped most models. Llama3 improved a lot with few-shot; Mixtral also jumped in few-shot. Mistral got its best score in CoT, but CoT hurt Llama3.

Invalid answers were rare overall for most models, but Mixtral zero-shot had 6.67\% invalid outputs and Llama3 CoT had 4.44\%. \texttt{openai/gpt-oss-20b} (Groq, reasoning model) was very strong in CoT (90.56\%) but had very high invalid rates in zero-shot/few-shot (53.33\%/47.78\%) because it often put answers in reasoning content instead of a clean final label.

\subsection*{\color{bambergnavy} Statistical significance (McNemar, paired exact test)}
I used paired exact McNemar tests because each model answers the same items. Some differences that look small are still meaningful, and some are not.
\begin{itemize}[leftmargin=*]
    \item \textbf{Llama3:latest:} few-shot was significantly better than zero-shot ($p = 0.0023$). Zero-shot was significantly better than CoT ($p = 0.0237$).
    \item \textbf{Mistral:7b:} CoT ($p = 0.0023$) and few-shot ($p = 0.0225$) were significantly better than zero-shot.
    \item \textbf{Mixtral:8x7b:} few-shot was significantly better than zero-shot ($p = 0.0094$); CoT vs zero-shot was not significant ($p = 0.8555$).
    \item \textbf{Qwen2.5:7b:} few-shot was significantly better than zero-shot ($p = 0.0391$); CoT vs zero-shot was not significant ($p = 0.1460$).
    \item \textbf{Model comparisons:} Qwen2.5:7b was significantly better than Llama3 and Mistral in all tested strategies, and better than Mixtral in zero-shot and CoT; Mixtral vs Qwen few-shot was close but not significant at 0.05 ($p = 0.0931$). Mistral vs Mixtral CoT was not significant ($p = 1.0$).
\end{itemize}
Full results are in \texttt{results/significance\_tests.csv}.

\subsection*{\color{bambergnavy} Error analysis (exploratory)}
The error labels are heuristic (rule-based), so I treat them as exploratory, not final truth. Still, the pattern is clear:
\begin{itemize}[leftmargin=*]
    \item World-knowledge over-entailment was the most common error for weaker models, especially Llama3 and Mistral. This matches the high false positive rates.
    \item Negation/presupposition/factivity errors appeared across models, showing that logical scope and trigger handling are still hard.
    \item Format errors were rare, but Mixtral zero-shot had 12 format errors in the heuristic attribution and 6.67\% invalid rate overall; this should be checked manually.
\end{itemize}
Full table: \texttt{results/error\_attribution.csv}. Figures: \texttt{results/category\_accuracy\_comparison.png} and \texttt{results/fp\_fn\_rates.png}.

\pdfbookmark[1]{11. Final thoughts}{11Finalthoughts}
\section*{\color{bambergnavy} 11. Final thoughts}
The main value of this project is that it gives a clear and simple way to test language models on meaning, not just fluency. The benchmark is small, but it is balanced and easy to inspect. The code now has better tests, better caching, run manifests, and clearer metric reporting. The real runs show that Cloudflare's Llama 3.3 70B variant achieved the highest scores across the tested backends, while \texttt{qwen2.5:7b} was the strongest local Ollama model. Mixtral was strong in few-shot, and Llama3/Mistral made many over-entailment mistakes, especially on plausible non-entailment. With more models and human label checks, this setup can give an even stronger and more trustworthy comparison.
